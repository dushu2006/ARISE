## 2. Production Execution Traces (Rule #2 & Rule #4)

### 2.1 Application & Backend Startup (`create_app` / `_build_services`)
1. **Desktop Entry:** `frontend/src-tauri/src/main.rs:launch_backend` (or `src/arise/supervisor.py:BackendSupervisor.start`) resolves `ARISE_BACKEND_EXECUTABLE`, bundled sidecar binary (`find_bundled_sidecar` / `resolve_backend_command`), or `python -m arise.server`, sets `ARISE_BACKEND_READY_SIGNAL=1` and `ARISE_PARENT_STDIN_WATCH=1`, and spawns the child process with a piped `stdin`.
2. **Backend Composition:** `arise.server:create_app` calls `_build_services(chosen_settings)`:
   - Acquires `DatabaseInstanceLock` inside `SQLiteDatabase(settings.database_path, acquire_instance_lock=True)` and applies migrations `v1..v9`.
   - Instantiates `SQLiteTaskRepository`, `SQLiteSessionRepository`, `EventBroker`, and `PublishingEventStore(SQLiteEventStore(database), broker)`.
   - Instantiates `ToolRegistry()`, `PolicyEngine()`, `ModelRouter(...)`, `CompositeSecretProvider(...)`, `SQLiteMemoryRepository(...)`, `PersonalizationStore(database)`, `ProceduralMemoryStore(database)`, `WorkingMemoryStore()`, and `ShortTermConversationMemory()`.
   - Registers `WindowsUiaProvider` + `uia.*` tools when `settings.desktop.enabled=True`, `PlaywrightBrowserProvider` + `browser.*` tools when `settings.browser.enabled=True`, and `PerceptionHierarchyPipeline` when `settings.perception.enabled=True`.
   - Instantiates `AgentRuntime(..., environment=CompositeEnvironment(...), resources=ResourceManager(), verifier=FactVerifier(environment))` and `TaskEngine(..., runtime=runtime, tools=tools, policy=policy, planner=planner)`.
   - Calls `_build_voice_runtime(...)` and constructs `CapabilityService` and `HealthService`.
3. **Lifespan Handshake:** `lifespan` runs `await services.engine.start()` (recovering any interrupted/waiting tasks from SQLite and starting worker tasks) and prints `ARISE_BACKEND_READY` to stdout.

### 2.2 Production Voice Path (Rule #4)
- **Composition Function:** `_build_voice_runtime` in `src/arise/server.py` (invoked by `_build_services`).
- **Constructed Graph:**
  `AudioHub` (`services.voice_hub`) owning:
  - `microphone = SoundDeviceMicrophone(...)`
  - `vad = WebRtcVadAdapter(...)`
  - `wake_word_detector = VoskWakeWordDetector(local_model, ...)`
  - `speech_recognizer = VoskSpeechRecognizer(local_model)`
  - `speech_synthesizer = LazyKokoroSpeechSynthesis(...)` (wrapping `KokoroSpeechSynthesis`)
  - `playback = SoundDeviceAudioPlayback(...)`
  - `provider = GeminiLiveProvider(...)`
  - `conversation_bridge = VoiceConversationBridge(TaskEngineVoiceAdapter(services.engine), informational_responder=_answer_voice_question)`
- **Verification of the Three Spoken Utterances (`ProductionRuntimeCompositionAuditTests`):**
  1. `"Tell me how to open Chrome"` → `IntentClassifier.classify` returns `IntentKind.QUESTION` (`may_require_runtime_task=False`) → `VoiceConversationBridge.process_utterance` invokes `_answer_voice_question` (`ModelRouter.complete` with `ModelRole.FAST_REASONER` and tool-free system prompt) → **zero tasks admitted** to `TaskEngine` → `AudioHub.speak_text` streams synthesized PCM chunks from `LazyKokoroSpeechSynthesis` into `playback.play`.
  2. `"Open Chrome"` → `IntentClassifier.classify` returns `IntentKind.COMMAND` (`confidence=0.92`, `may_require_runtime_task=True`) → `VoiceConversationBridge._execute_task` submits `UserRequest(text="Open Chrome", source=RequestSource.VOICE)` through `TaskEngineVoiceAdapter` to `services.engine` (`TaskEngine`) → `GatewayTaskPlanner` → `PolicyEngine` → `ResourceManager` → `AgentRuntime` → `FactVerifier` → `TaskStatus.COMPLETED`, while `AudioHub` synthesizes the local acknowledgement via `LazyKokoroSpeechSynthesis` → `playback.play` and monitors task completion via `_start_task_monitor`.
  3. `"Open Chrome and then search for X"` → `IntentClassifier.classify` returns `IntentKind.MULTI_STEP_TASK` (`confidence=0.96`, `structured_command.steps=(open, search)`) → admitted to `services.engine` (`TaskEngine`) → `GatewayTaskPlanner` creates a 2-step `TaskPlan` with `depends_on=("step-open",)` → both steps execute and pass `FactVerifier` → `TaskStatus.COMPLETED`.

### 2.3 Perception reachability boundary

`POST /api/v1/perception/resolve` is authenticated. When enabled, it inspects the active Playwright page (if started), inspects the foreground UIA window (if registered/available), optionally captures a screenshot, then calls `PerceptionHierarchyPipeline.resolve_hierarchical`; the resolver prioritizes structural DOM/UIA candidates before OCR and vision. The coordinate gate receives the configured explicit opt-in and unsafe-region rectangles, while freshness/DPI/focus/human-interference facts remain false unless separately established, so it fails closed in the API route.

The response is a target proposal with `authority="untrusted_grounding_requires_policy_and_verifier"`. The route does **not** create a task or execute an action. Browser and UIA actions separately enter through `TaskEngine` and their registered tools; OCR/vision-only candidates returned by this resolver are not yet fed into the TaskEngine action target/dispatch path. Therefore the resolver route is production-reachable as a read-only perception service, but a perception-only target-to-action end-to-end path is not validated or claimed. This boundary prevents OCR/vision results from directly gaining action authority.

## 3. Dead / Unwired Implementations Found and Remediated During This Audit (Rule #3)

During this forensic audit of `src/arise/server.py` and `src/arise/config/settings.py`, the following adapters existed in `src/arise/` and were tested in unit tests, but were **not wired into `_build_services()` / `_build_voice_runtime()` in `src/arise/server.py`**. All 6 were fixed in this audit:

1. **Local TTS (`KokoroSpeechSynthesis`) not wired into `_build_voice_runtime`:** Added `LazyKokoroSpeechSynthesis` (`src/arise/adapters/audio_local.py`), added `kokoro_model_path`, `kokoro_voices_path`, `tts_voice`, and `enable_local_tts_acknowledgement` to `VoiceSettings` (`src/arise/config/settings.py`), and wired `speech_synthesizer` into `AudioHub` in `_build_voice_runtime` (`src/arise/server.py`).
2. **Voice Question Answering (`"Tell me how to open Chrome"`) not wired to `ModelRouter` in `VoiceConversationBridge`:** Added `informational_responder` and `process_utterance` to `VoiceConversationBridge` (`src/arise/core/voice_bridge.py`), `process_spoken_utterance` to `AudioHub` (`src/arise/core/voice.py`), `_answer_voice_question` in `_build_voice_runtime`, and `POST /api/v1/voice/utterance` in `src/arise/server.py`.
3. **Bug in `_answer_voice_question` calling `router.complete(req, sel)` positionally:** Fixed to `await router.complete(req, selection=sel)` because `selection` is keyword-only on `ModelRouter.complete`.
4. **`WindowsUiaProvider` and `PlaywrightBrowserProvider` not wired in `_build_services`:** Added `DesktopSettings` and `BrowserSettings` to `AppSettings` (`src/arise/config/settings.py`), wired `WindowsUiaProvider`, `register_windows_uia_tools`, `PlaywrightBrowserProvider`, `register_playwright_tools`, and `CompositeEnvironment` in `_build_services` (`src/arise/server.py`), and added `browser_provider.close()` to `create_app` lifespan teardown.
5. **`PerceptionHierarchyPipeline` and `ScreenCaptureAdapter` not wired in `_build_services`:** Added `PerceptionSettings` to `AppSettings`, wired `ScreenCaptureAdapter` (including `displays_fn`, `windows_fn`, `foreground_window_fn` from `uia_provider`), `OcrPerceptionAdapter`, `VisionGroundingAdapter`, `CoordinateFallbackSafetyGate`, and `PerceptionHierarchyPipeline` into `_build_services`, updated `CapabilityService` (`vision.ocr`), and added `POST /api/v1/perception/resolve`.
6. **`WorkingMemoryStore`, `ShortTermConversationMemory`, and `LocalDeterministicEmbeddingAdapter` not wired in `_build_services`:** Wired `WorkingMemoryStore` and `ShortTermConversationMemory` into `ServerServices` and `interact_with_text`, wired `LocalDeterministicEmbeddingAdapter` when `embeddings.use_local_fallback=True`, and added `POST /api/v1/workflows/{workflow_id}/adapt`.
7. **`Win32ScreenCaptureBackend.capture_rect` stub and `capture_full_screen` method name mismatch:** Implemented Win32 GDI `GetDC(0)` → `CreateCompatibleDC` → `CreateCompatibleBitmap` → `SelectObject` → `BitBlt(SRCCOPY)` → `GetDIBits` with BGRA-to-RGBA conversion and deterministic handle cleanup in `Win32ScreenCaptureBackend` (`src/arise/adapters/perception.py`), added `ScreenCaptureAdapter.capture_screen` alias for `capture_desktop`, and fixed `/api/v1/perception/resolve` in `src/arise/server.py` to call `capture_desktop()`.
8. **`Win32UiaBackend` low-level Win32 control-tree and action dispatch stubs:** Implemented multi-monitor `EnumDisplayMonitors`/`GetMonitorInfoW`/`GetDpiForMonitor`, top-level `EnumWindows`, child control `EnumChildWindows` (`GetClassNameW`, `GetWindowTextW`, `GetDlgCtrlID`, `GetWindowRect`, `ES_PASSWORD` detection), `GetLastInputInfo` user-interference detection, and `SendMessageW`/`PostMessageW` (`BM_CLICK`, `WM_SETTEXT`, `WM_SETFOCUS`, `WM_KEYDOWN`/`WM_KEYUP`/`WM_CHAR`) in `Win32UiaBackend` (`src/arise/adapters/windows_uia.py`), verified by `test_win32_screen_capture_backend_and_win32_uia_backend_contracts` in `tests/test_windows_uia_and_perception.py`.
