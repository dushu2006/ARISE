**Protocol:** Zero-hallucination, checklist-driven execution. Every requirement is an individual checkbox with a per-item evidence record. FAKE/REPLAY/SIMULATION tests are never relabelled as real device/provider/Windows execution.
**Status key (only):** `[ ] NOT VALIDATED` · `[x] REAL VALIDATED` · `[!] ENVIRONMENT BLOCKED` · `[?] EXTERNAL CONFIGURATION REQUIRED` · `[FAIL] FAILED`.
**Validated checkout:** branch `arena/01a10306-arise`; first cycle at commit `2d8c0a7e46bc47124866932d1e70cbe2ba2f468f` and `9c132f3`, then re-executed in this cycle on `9c132f3` with the uncommitted release-gate fixes (redaction, workflow-adapt route, browser discovery, and 4 new/extended test files). Host Linux x86_64, Python 3.11.2, Node 22.22.3, `playwright` 1.63.0 wheel installed with no Chromium binary, no cargo/rustc, no local Chromium. No interactive Windows desktop, audio device, or WebView2 is attached.
**Evidence classes:** REAL=production code/actual OS/process/provider execution; FAKE=injected adapter/provider; REPLAY=recorded/synthetic frame/audio; SIMULATION=deterministic in-memory tool/environment; ENVIRONMENT-BLOCKED=required OS/hardware/runtime absent; EXTERNAL-CONFIGURATION=required credential/model/device/browser/runtime absent. Evidence classes may overlap within an item.
**Per-item fields:** Implementation; Production wiring; Real execution; Test evidence; Environment; External config; Final status. `[x]` is only for the exact software criterion named (e.g. a guard or command); it never upgrades FAKE/REPLAY/SIMULATION into live host evidence.
**Execution completed top-to-bottom:** A–N each has a justified status below (section N was added by this validation cycle to record the defects found and their re-verification). Final `NOT VALIDATED` count is required to be zero; all remaining limitations are explicitly `[!]` or `[?]`.
